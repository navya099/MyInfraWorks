# MyInfraWorks

MyInfraWorks는 infraworks 대체 프레임워크를 개발하는 프로젝트입니다.

대한민국 SRTM 30m DEM을 활용한 Windows용 개략 노선설계 도구를 개발합니다. 목표 범위는 기본계획·예비타당성 검토 수준의 평면·종단선형, 종단·횡단 뷰, 지형 메시, 실시간 절성토 지형 미리보기입니다.

## 현재 상태

- `legacy/wpf`: 작동하는 WPF 시제품 0.2. DEM 열기, 직선 노선 작성, 계획고 변경, 종단·횡단·3D 표시, 단순 사면, 프로젝트 저장·복원을 지원합니다.
- `godot`: Godot + C++ 편집기 시제품 0.6. 원본 해상도 수준의 계산용 지형과 화면용 지형을 분리합니다. DEM 지형, Orbit/Pan/Zoom, 평면 노선, 종단 계획고 드래그, 횡단, 단순 절성토, 프로젝트 저장을 지원합니다. 지형은 타일로 나누고 C++ 작업 스레드에서 계산하며, 노선의 영향 구간만 갱신합니다.
- `tests`: WPF 계산 검사와 두 DEM 변환기 검사입니다. Godot 네이티브·편집기 검사는 아래 명령을 참조하세요.

## 준비

- Windows x64
- Visual Studio 2022: C++ 데스크톱 개발, MSVC v143, Windows SDK/UCRT
- Python 3.11 이상 / Git
- Godot 4.7.2 표준 Windows 버전
- WPF 시제품에만 .NET 9 SDK 필요

```powershell
git clone --recurse-submodules https://github.com/navya099/MyInfraWorks.git
cd MyInfraWorks
python -m pip install -r requirements-dev.txt
```

이미 복제했다면 `git submodule update --init --recursive`를 실행합니다. Godot 실행 파일은 별도로 설치합니다. `godot-cpp`는 검증한 4.5 API 커밋으로 고정되어 있고, 해당 확장의 Godot 4.7.2 로드를 확인했습니다. 의존성 소스의 라이선스는 해당 서브모듈을 참조하세요.

## WPF 시제품 실행

```powershell
dotnet run --project legacy/wpf/KRoadPrototype.csproj -c Release
```

시작 시 합성 지형이 표시됩니다. `DEM 열기`로 GeoTIFF를 선택합니다.

1. 평면 지형 안을 차례대로 클릭해 노선 점을 추가합니다.
2. 종단에서 클릭하면 측점상 가장 가까운 제어점의 계획고가 바뀝니다.
3. 폭·높이 보정·사면비를 입력하고 적용합니다. 사면비는 H:V입니다.
4. 횡단 슬라이더로 측점을 선택합니다. 초록은 원지반, 주황은 계획입니다.
5. 3D에서 드래그로 회전하고 휠로 확대합니다.
6. `.kroad` 형식으로 저장하고 다시 열 수 있습니다.

실제 DEM 로드는 Python의 rasterio를 사용합니다. EPSG:5179 수평 좌표계로 재투영하고 최대 161×161 격자로 축소합니다. 높이는 미터라고 가정하고 수직 기준 변환은 하지 않습니다. 원본 DEM을 수정하지 않습니다.

제한: DEM 한 타일, 직선 연결 노선·구배, 단순 사면만 지원합니다. 원곡선·완화곡선·종단곡선·편경사·토공량·실행 취소는 아직 없습니다. 축소 격자보다 좁은 도로·사면의 3D 표현은 부정확할 수 있습니다. 복잡한 사면 중첩과 도로 끝단 사면은 처리하지 않습니다.

## Godot 편집기 0.6 실행

C++ 빌드 후 실행합니다.

```powershell
godot --path godot/project
```

이 PC에서는 `run-godot.cmd`를 두 번 클릭해도 됩니다. 런처는 형제 폴더의 Godot 4.7.2 실행 파일을 찾습니다. 다른 PC에서는 `GODOT_BIN` 환경 변수로 실행 파일 경로를 지정하세요. 런처가 시작한 프로세스의 사용자 데이터는 저장소의 무시된 `work/appdata/`에 둡니다. 전역 환경 설정은 바꾸지 않습니다.

- 평면 클릭: 노선 점 추가. 마지막 점 취소 / 노선 초기화 지원.
- 종단에서 드래그: 수평 측점상 가까운 제어점의 계획고 변경. 드래그 동안 세로 축 범위는 고정됩니다.
- 3D 왼쪽 드래그: Orbit. 오른쪽 또는 가운데 드래그: Pan. 휠: Zoom.
- 폭·높이 보정·사면비 변경 후 적용. 횡단 슬라이더로 측점 선택.
- `.kroadg`로 저장·불러오기. 새 프로젝트는 곡선 매개변수와 계산용 높이를 함께 저장하는 바이너리 v3 형식입니다. 기존 Godot v1 JSON 및 v2 프로젝트도 열 수 있습니다. WPF의 `.kroad`와는 다릅니다.
- `측점 보기`: 선택한 횡단 측점의 도로·사면을 3D에서 가까이 봅니다.
- 새 DEM 또는 프로젝트를 열면 현재 설계를 교체합니다. 작업을 먼저 저장하세요.

DEM 가져오기는 Python/rasterio를 작업 스레드에서 실행합니다. EPSG:5179로 원본 해상도 수준을 유지해 재투영한 계산용 격자(float32)와, 같은 범위의 최대 513×513 화면용 격자를 만듭니다. 종단·횡단·사면 높이는 계산용 격자를 조회합니다. 재투영·보간을 거치므로 원본 TIFF 픽셀을 그대로 조회하는 방식은 아니며, DEM의 실제 정확도가 향상되는 것은 아닙니다. 높이는 미터로 가정하고 수직 기준을 변환하지 않습니다. 한 파일, 계산용 최대 6,400만 표본을 지원합니다.

C++는 직선·원곡선·클로소이드, 곡선 길이 기준 측점, 포물선 종단곡선, 도로 리본과 지형 메시를 계산합니다. 토공량, 편경사와 복잡한 사면 처리는 미구현입니다. 도로 주변은 적응형으로 세분화하지만 도로 경계·사면 접속선을 정확히 따르는 삼각망은 아직 아닙니다. 격자 정렬과 세분화 상한에 따라 도로 리본과 지형이 일부 겹쳐 보일 수 있습니다. 원지형/계획지형의 비교 토글은 없습니다.

렌더링 타일의 기준 범위는 화면용 32×32 셀입니다. 도로·사면 영향 셀은 최대 가로·세로 각각 16배 세분화합니다. 세분화 배수는 계산용 지형 간격과 도로 폭으로 결정하며, 낮은 해상도 이웃 셀은 경계 팬 삼각형으로 연결합니다. 타일 사이에서도 같은 전역 격자 위치와 법선을 사용합니다. 멀리 있는 타일의 카메라 거리 기반 LOD는 아직 없습니다. 변경 전·후 노선의 보수적인 영향 범위에 해당하는 타일만 계산합니다. 영향 범위는 노선 전체 구간의 사면을 포함하므로, 긴 노선은 많은 타일을 다시 계산할 수 있습니다. 편집 요청은 버전으로 구분해 오래된 계산 결과를 버립니다. GPU 메시 반영은 프레임당 최대 2개 타일로 제한합니다. 세분화된 타일은 기존 타일보다 크므로 지형 규모와 노선 길이에 따라 업로드 비용이 달라집니다. 드래그 중 도로/차트가 먼저 변하고 지형은 계산 완료 후 따라옵니다. 카메라 조작은 계산과 메시 생성에 관여하지 않습니다.

이 값은 합성 데이터의 개발 측정이며 사용자 SRTM 원본에서의 정확도나 일정한 FPS를 보장하지 않습니다. 개발 샌드박스에서 인증서 저장소 읽기 경고가 발생하지만 로컬 계산·렌더링 검사는 통과했습니다.


## 0.4 검증 및 데이터 형식 (2026-11-10)

- 계산용 지형과 화면용 지형은 첫·마지막 픽셀 중심, 원점, 전체 범위를 일치시킵니다. 화면 격자에는 없는 1픽셀 봉우리도 계산용 높이 조회에서는 보존되는 검사를 통과했습니다.
- float32 높이, NoData, 원점/범위 불일치, 적응형 셀 경계의 위치·법선, 열린 내부 변 없는 삼각망, 노선 초기화 후 원지형 복원을 검사합니다.
- 가져오기 중 계산용 높이는 JSON 옆 임시 `.f32`에 저장하고, 애플리케이션이 메모리로 읽은 뒤 임시 파일을 제거합니다. 원본 TIFF는 수정하지 않습니다.
- 새 `.kroadg`는 `KROAD2` 헤더와 Godot Variant 바이너리로, 화면·계산 격자와 노선을 한 파일에 저장합니다. 객체 역직렬화는 허용하지 않습니다. 저장은 작업 스레드에서 임시 파일을 완성한 뒤 대상 파일을 교체합니다. TIFF나 캐시가 없어도 다시 열 수 있습니다.
- v1 프로젝트는 기존 화면용 높이만 보유합니다. 해당 파일을 여는 것만으로 원본 해상도가 복원되지는 않습니다. 원본 DEM을 다시 가져오면 현재 노선이 교체되므로 별도로 저장하고 진행하세요.

GTX 1060 6GB / OpenGL Compatibility에서 합성 3601×3601, 30m 투영 DEM(계산 표본 약 1,300만 개, 화면 513×513)을 가져와 측정한 값:

- Orbit 120프레임: 평균 13.33ms, p95 13.41ms. 지형 업로드 0회.
- 종단 드래그 + Orbit 60프레임: 중앙값 15.86ms, p95 19.29ms. 해당 편집은 256타일 중 4타일 갱신.

합성 데이터의 관측값이며 실제 사용자 DEM과 긴 노선에서 같은 성능을 보장하지 않습니다. 위 0.4 측정은 직선 연결 노선 기준입니다. 0.5 곡선 노선 측정은 아래를 참조하세요.


## 0.5 선형 설계 사용법

기존 실행 창을 저장하고 닫은 뒤 `run-godot.cmd`를 다시 실행합니다. 실행 중인 0.4의 DLL을 덮어쓰지 않도록 새 DLL 이름 `kroad_core_v05...dll`을 사용합니다.

1. DEM을 열고 평면에 PI를 세 개 이상 추가합니다.
2. `선형 제어점`에서 내부 PI를 선택합니다. 평면 우클릭으로 가까운 PI를 선택할 수도 있습니다. 시점·종점에는 곡선을 설정하지 않습니다.
3. `R(m)`에 원곡선 반지름, `완화 Ls(m)`에 진입·진출 각각의 클로소이드 길이, `종단 Lv(m)`에 대칭 포물선 종단곡선 전체 길이를 입력합니다.
4. `곡선 적용`을 누릅니다. 예: 접선 구간이 충분한 90도 PI에서 R=500, Ls=100, Lv=400.
5. R=0, Ls=0은 기존 직선 연결입니다. R>0, Ls=0은 원곡선만 사용합니다. R>0, Ls>0은 직선–완화–원곡선–완화–직선입니다. Lv=0은 기존 직선 구배입니다.
6. 종단에서 드래그하거나 `PVI고(m)`와 `표고 적용`으로 선택 PVI 제어고를 바꿉니다. 하늘색 표시는 종단곡선의 시작·끝이며, 주황 제어점은 PVI입니다. 포물선은 일반적으로 PVI를 직접 통과하지 않습니다.
7. `곡선표`에서 요소별 측점·길이·곡률과 종단곡선 시작·끝 측점, 전후 구배, K값(m/%)을 확인합니다. 평면에는 BC/EC 또는 TS/SC/CS/ST를 표시합니다.
8. `.kroadg`로 저장하면 R, Ls, Lv와 설계 제어점이 복원됩니다.

현재 종단 PVI는 평면 제어점과 연결됩니다. 곡선이 있는 내부 PI의 대응 측점은 해당 평면 곡선의 길이상 중앙입니다. **이 측점은 접선 교점 PI 자체의 측점 표기와 다릅니다.** R 또는 Ls를 바꾸면 대응 PVI 측점과 구배도 바뀝니다. 독립적인 PVI 추가·측점 이동과 비대칭 종단곡선은 아직 지원하지 않습니다.

수용할 수 없는 반지름·완화길이, 170도 이상의 반전 곡선, 평면 곡선의 접선 구간 중첩, 종단곡선 중첩 및 노선 끝을 넘는 종단곡선은 적용하지 않고 기존 설계를 유지합니다. 반경은 도로 폭의 절반보다 커야 합니다. 이 검사는 기하 구성 검사이며 국내 도로·철도 설계 기준이나 시거 검사를 대체하지 않습니다.

곡선 본체와 측점·방향·곡률·표고·구배는 C++에서 계산합니다. 지형 사면은 해당 선형을 수평 현오차 목표 0.05m, 종단 선분 보간오차 목표 0.01m, 최대 간격 25m로 분할한 폴리라인에 대해 계산합니다. 이는 DEM의 측량 정확도를 높이지 않습니다. 가장 가까운 분할 선분을 공간 버킷으로 검색하며, 끝점 주변은 가장 가까운 끝점까지의 거리로 처리합니다. 자기 교차·교차로·복층 구조물과 상세 노선 단부 토공은 별도 구현이 필요합니다.

수학과 자료 구조는 [선형 코어 설명](docs/alignment.md)을 참조하세요.

## 0.6 PI 편집과 실행 취소 (2026-11-12)

기존 실행 창을 저장하고 닫은 뒤 같은 `run-godot.cmd`를 실행합니다. C++ DLL 및 프로젝트 저장 형식(v3)은 0.5와 같습니다.

- 평면의 PI에서 왼쪽 버튼을 누르고 드래그하면 위치가 바뀝니다. 12픽셀 안의 가까운 PI를 선택하며, 3픽셀 이상 움직인 뒤 이동을 시작합니다. 빈 곳 클릭은 기존처럼 PI 추가입니다. 가까운 PI에 잡히지 않고 새 점을 넣으려면 Shift+클릭합니다.
- 선택된 PI는 하늘색 테두리로 표시합니다. 내부 PI뿐 아니라 시·종점도 이동할 수 있습니다.
- `로컬 동 X(m)`, `로컬 남 Y(m)`를 입력하고 `PI 위치 적용`을 눌러 수치로 이동할 수 있습니다. 좌표 원점은 지형 북서쪽 첫 픽셀 중심이며 Y는 남쪽으로 증가합니다. 실제 DEM에서는 선택 위치의 EPSG:5179 E/N도 표시합니다.
- 위치만 바꾸면 PVI 제어고는 유지합니다. 평면 길이와 연결된 PVI 대응 측점·구배는 재계산됩니다. 지형 높이로 PVI고를 자동 재설정하지 않습니다.
- 범위 밖·NoData·중복점·곡선 중첩 등 유효하지 않은 위치는 적용하지 않습니다. 드래그 중에는 마지막 유효 설계를 유지하며, 거절된 커서 위치를 빨간 원으로 표시합니다.
- Esc 또는 창의 포커스 상실은 진행 중인 평면·종단 드래그를 취소하고 시작 상태로 복원합니다. 버튼을 놓으면 마지막 유효 위치로 확정합니다.
- `실행 취소` / Ctrl+Z, `다시 실행` / Ctrl+Y 또는 Ctrl+Shift+Z를 지원합니다. 한 번의 평면·종단 드래그는 한 단계로 기록합니다. 입력란에 포커스가 있으면 단축키는 해당 입력란의 텍스트 편집에 맡깁니다.
- PI 추가·마지막 점 삭제·노선 초기화·좌표 이동·PVI 표고·R/Ls/Lv·폭/보정/사면비를 최근 100단계까지 복원합니다. 새 편집을 하면 redo 이력이 지워집니다. 이력에는 설계 매개변수만 저장하고 DEM·파생 메시를 넣지 않습니다.
- 카메라·횡단 선택 측점·DEM 교체는 실행 취소 대상이 아닙니다. 다른 DEM 또는 프로젝트를 열거나 데모로 바꾸면 이력을 초기화합니다. 프로젝트에는 최종 설계만 저장하며 이력은 저장하지 않습니다.

godot --path godot/project -- --visual-test "C:/absolute/path/edit-preview.png" --curve-demo --pi-drag-test
