# MyInfraWorks

개발 브랜치: `feature/plan-dxf-station-labels` (0.31). 확인된 0.30는 `main`에 반영했습니다.

MyInfraWorks는 infraworks 대체 프레임워크를 개발하는 프로젝트입니다.

대한민국 SRTM 30m DEM을 활용한 Windows용 개략 노선설계 도구를 개발합니다. 목표 범위는 기본계획·예비타당성 검토 수준의 평면·종단선형, 종단·횡단 뷰, 지형 메시, 실시간 절성토 지형 미리보기입니다.

## 현재 상태

- `legacy/wpf`: 작동하는 WPF 시제품 0.2. DEM 열기, 직선 노선 작성, 계획고 변경, 종단·횡단·3D 표시, 단순 사면, 프로젝트 저장·복원을 지원합니다.
- `godot`: Godot + C++ 편집기 시제품 0.31. 원본 해상도 수준의 계산용 지형과 화면용 지형을 분리합니다. DEM 지형, Orbit/Pan/Zoom, 평면 노선, 종단 계획고 드래그, 횡단, 단순 절성토, 프로젝트 저장을 지원합니다. 지형은 타일로 나누고 C++ 작업 스레드에서 계산하며, 노선의 영향 구간만 갱신합니다.
- `tests`: WPF 계산 검사와 두 DEM 변환기 검사입니다. Godot 네이티브·편집기 검사는 아래 명령을 참조하세요.

## WPF 시제품 실행

```powershell
dotnet run --project legacy/wpf/KRoadPrototype.csproj -c Release
```

시작 시 합성 지형이 표시됩니다. `DEM 열기`로 GeoTIFF를 선택합니다.

1. 평면 지형 안을 차례대로 클릭해 노선 점을 추가합니다.
2. 종단에서 클릭하면 측점상 가장 가까운 제어점의 계획고가 바뀝니다.
3. 폭·높이 보정·사면비를 입력하고 적용합니다. 사면비는 H:V입니다.
4. 횡단 슬라이더로 측점을 선택합니다. 초록은 원지반, 주황은 계획입니다.
5. 3D에서 드래그로 회전하고 휠로 확대합니다.
6. `.kroad` 형식으로 저장하고 다시 열 수 있습니다.

실제 DEM 로드는 Python의 rasterio를 사용합니다. EPSG:5179 수평 좌표계로 재투영하고 최대 161×161 격자로 축소합니다. 높이는 미터라고 가정하고 수직 기준 변환은 하지 않습니다. 원본 DEM을 수정하지 않습니다.

제한: DEM 한 타일, 직선 연결 노선·구배, 단순 사면만 지원합니다. 원곡선·완화곡선·종단곡선·편경사·토공량·실행 취소는 아직 없습니다. 축소 격자보다 좁은 도로·사면의 3D 표현은 부정확할 수 있습니다. 복잡한 사면 중첩과 도로 끝단 사면은 처리하지 않습니다.

## Godot 편집기 0.31 실행

C++ 빌드 후 실행합니다.

```powershell
godot --path godot/project
```

이 PC에서는 `run-godot.cmd`를 두 번 클릭해도 됩니다. 런처는 형제 폴더의 Godot 4.7.2 실행 파일을 찾습니다. 다른 PC에서는 `GODOT_BIN` 환경 변수로 실행 파일 경로를 지정하세요. 런처가 시작한 프로세스의 사용자 데이터는 저장소의 무시된 `work/appdata/`에 둡니다. 전역 환경 설정은 바꾸지 않습니다.

- 평면 기본 상태: PI 선택·이동. 평면 아래 `PI 추가` 버튼을 켠 상태에서만 클릭으로 노선 끝에 점을 추가합니다. Esc로 추가 모드를 종료합니다. 마지막 점 취소 / 노선 초기화 지원.
- 종단에서 드래그: 수평 측점상 가까운 제어점의 계획고 변경. 드래그 동안 세로 축 범위는 고정됩니다.
- 3D 왼쪽 드래그: Orbit. 오른쪽 또는 가운데 드래그: Pan. 휠: Zoom.
- 폭·높이 보정·사면비 변경 후 적용. 횡단 슬라이더로 측점 선택.
- `.kroadg`로 저장·불러오기. 새 프로젝트는 독립 PVI·횡단구배·절토/성토 사면비와 계산용 높이를 저장하는 바이너리 v7 형식입니다. 기존 v1 JSON 및 v2/v3 프로젝트는 기존 종단 형상을 보존해 독립 PVI로 변환합니다. v1~v4의 횡단구배는 0%로 보존합니다. 0.18 이하 앱은 v7을 열 수 없습니다. WPF의 `.kroad`와는 다릅니다.
- `측점 보기`: 선택한 횡단 측점의 도로·사면을 3D에서 가까이 봅니다.
- 새 DEM 또는 프로젝트를 열면 현재 설계를 교체합니다. 작업을 먼저 저장하세요.

DEM 가져오기는 Python/rasterio를 작업 스레드에서 실행합니다. EPSG:5179로 원본 해상도 수준을 유지해 재투영한 계산용 격자(float32)와, 같은 범위의 최대 513×513 화면용 격자를 만듭니다. 종단·횡단·사면 높이는 계산용 격자를 조회합니다. 재투영·보간을 거치므로 원본 TIFF 픽셀을 그대로 조회하는 방식은 아니며, DEM의 실제 정확도가 향상되는 것은 아닙니다. 높이는 미터로 가정하고 수직 기준을 변환하지 않습니다. 한 파일, 계산용 최대 6,400만 표본을 지원합니다.

C++는 직선·원곡선·클로소이드, 곡선 길이 기준 측점, 포물선 종단곡선, 도로 리본과 지형 메시를 계산합니다. 토공량, 편경사와 복잡한 사면 처리는 미구현입니다. 도로 주변은 적응형으로 세분화하지만 도로 경계·사면 접속선을 정확히 따르는 삼각망은 아직 아닙니다. 격자 정렬과 세분화 상한에 따라 도로 리본과 지형이 일부 겹쳐 보일 수 있습니다. 원지형/계획지형의 비교 토글은 없습니다.

렌더링 타일의 기준 범위는 화면용 32×32 셀입니다. 도로·사면 영향 셀은 최대 가로·세로 각각 16배 세분화합니다. 세분화 배수는 계산용 지형 간격과 도로 폭으로 결정하며, 낮은 해상도 이웃 셀은 경계 팬 삼각형으로 연결합니다. 타일 사이에서도 같은 전역 격자 위치와 법선을 사용합니다. 멀리 있는 타일의 카메라 거리 기반 LOD는 아직 없습니다. 변경 전·후 노선의 보수적인 영향 범위에 해당하는 타일만 계산합니다. 영향 범위는 노선 전체 구간의 사면을 포함하므로, 긴 노선은 많은 타일을 다시 계산할 수 있습니다. 편집 요청은 버전으로 구분해 오래된 계산 결과를 버립니다. GPU 메시 반영은 프레임당 최대 2개 타일로 제한합니다. 세분화된 타일은 기존 타일보다 크므로 지형 규모와 노선 길이에 따라 업로드 비용이 달라집니다. 드래그 중 도로/차트가 먼저 변하고 지형은 계산 완료 후 따라옵니다. 카메라 조작은 계산과 메시 생성에 관여하지 않습니다.

## 0.4 검증 및 데이터 형식 (2026-11-10)

- 계산용 지형과 화면용 지형은 첫·마지막 픽셀 중심, 원점, 전체 범위를 일치시킵니다. 화면 격자에는 없는 1픽셀 봉우리도 계산용 높이 조회에서는 보존되는 검사를 통과했습니다.
- float32 높이, NoData, 원점/범위 불일치, 적응형 셀 경계의 위치·법선, 열린 내부 변 없는 삼각망, 노선 초기화 후 원지형 복원을 검사합니다.
- 가져오기 중 계산용 높이는 JSON 옆 임시 `.f32`에 저장하고, 애플리케이션이 메모리로 읽은 뒤 임시 파일을 제거합니다. 원본 TIFF는 수정하지 않습니다.
- 새 `.kroadg`는 `KROAD2` 헤더와 Godot Variant 바이너리로, 화면·계산 격자와 노선을 한 파일에 저장합니다. 객체 역직렬화는 허용하지 않습니다. 저장은 작업 스레드에서 임시 파일을 완성한 뒤 대상 파일을 교체합니다. TIFF나 캐시가 없어도 다시 열 수 있습니다.
- v1 프로젝트는 기존 화면용 높이만 보유합니다. 해당 파일을 여는 것만으로 원본 해상도가 복원되지는 않습니다. 원본 DEM을 다시 가져오면 현재 노선이 교체되므로 별도로 저장하고 진행하세요.

GTX 1060 6GB / OpenGL Compatibility에서 합성 3601×3601, 30m 투영 DEM(계산 표본 약 1,300만 개, 화면 513×513)을 가져와 측정한 값:

- Orbit 120프레임: 평균 13.33ms, p95 13.41ms. 지형 업로드 0회.
- 종단 드래그 + Orbit 60프레임: 중앙값 15.86ms, p95 19.29ms. 해당 편집은 256타일 중 4타일 갱신.

합성 데이터의 관측값이며 실제 사용자 DEM과 긴 노선에서 같은 성능을 보장하지 않습니다. 위 0.4 측정은 직선 연결 노선 기준입니다. 0.5 곡선 노선 측정은 아래를 참조하세요.


## 0.5 사용법 기록 (0.7은 아래 독립 PVI 사용법 참조)

기존 실행 창을 저장하고 닫은 뒤 `run-godot.cmd`를 다시 실행합니다. 실행 중인 0.4의 DLL을 덮어쓰지 않도록 새 DLL 이름 `kroad_core_v05...dll`을 사용합니다.

1. DEM을 열고 평면에 PI를 세 개 이상 추가합니다.
2. `선형 제어점`에서 내부 PI를 선택합니다. 평면 우클릭으로 가까운 PI를 선택할 수도 있습니다. 시점·종점에는 곡선을 설정하지 않습니다.
3. `R(m)`에 원곡선 반지름, `완화 Ls(m)`에 진입·진출 각각의 클로소이드 길이, `종단 Lv(m)`에 대칭 포물선 종단곡선 전체 길이를 입력합니다.
4. `곡선 적용`을 누릅니다. 예: 접선 구간이 충분한 90도 PI에서 R=500, Ls=100, Lv=400.
5. R=0, Ls=0은 기존 직선 연결입니다. R>0, Ls=0은 원곡선만 사용합니다. R>0, Ls>0은 직선–완화–원곡선–완화–직선입니다. Lv=0은 기존 직선 구배입니다.
6. 종단에서 드래그하거나 `PVI고(m)`와 `표고 적용`으로 선택 PVI 제어고를 바꿉니다. 하늘색 표시는 종단곡선의 시작·끝이며, 주황 제어점은 PVI입니다. 포물선은 일반적으로 PVI를 직접 통과하지 않습니다.
7. `곡선표`에서 요소별 측점·길이·곡률과 종단곡선 시작·끝 측점, 전후 구배, K값(m/%)을 확인합니다. 평면에는 BC/EC 또는 TS/SC/CS/ST를 표시합니다.
8. `.kroadg`로 저장하면 R, Ls, Lv와 설계 제어점이 복원됩니다.

현재 종단 PVI는 평면 제어점과 연결됩니다. 곡선이 있는 내부 PI의 대응 측점은 해당 평면 곡선의 길이상 중앙입니다. **이 측점은 접선 교점 PI 자체의 측점 표기와 다릅니다.** R 또는 Ls를 바꾸면 대응 PVI 측점과 구배도 바뀝니다. 독립적인 PVI 추가·측점 이동과 비대칭 종단곡선은 아직 지원하지 않습니다.

수용할 수 없는 반지름·완화길이, 170도 이상의 반전 곡선, 평면 곡선의 접선 구간 중첩, 종단곡선 중첩 및 노선 끝을 넘는 종단곡선은 적용하지 않고 기존 설계를 유지합니다. 반경은 도로 폭의 절반보다 커야 합니다. 이 검사는 기하 구성 검사이며 국내 도로·철도 설계 기준이나 시거 검사를 대체하지 않습니다.

곡선 본체와 측점·방향·곡률·표고·구배는 C++에서 계산합니다. 지형 사면은 해당 선형을 수평 현오차 목표 0.05m, 종단 선분 보간오차 목표 0.01m, 최대 간격 25m로 분할한 폴리라인에 대해 계산합니다. 이는 DEM의 측량 정확도를 높이지 않습니다. 가장 가까운 분할 선분을 공간 버킷으로 검색하며, 끝점 주변은 가장 가까운 끝점까지의 거리로 처리합니다. 자기 교차·교차로·복층 구조물과 상세 노선 단부 토공은 별도 구현이 필요합니다.

수학과 자료 구조는 [선형 코어 설명](docs/alignment.md)을 참조하세요.

## 0.9 평면 PI 중간 삽입·삭제 (main 반영 완료)

기존 창을 저장하고 닫은 뒤 같은 `run-godot.cmd`를 실행하세요. 이번 변경은 GDScript 편집 기능이며 C++ DLL은 검증한 `kroad_core_v08`을 그대로 사용합니다. 프로젝트 형식도 v4입니다.

1. 평면에서 우클릭하거나 `선형 제어점` 목록으로 삽입 앞쪽 PI를 선택합니다.
2. `PI 뒤에 삽입…`에서 로컬 동 X·남 Y를 입력하고 `입력 좌표 삽입`을 누릅니다. 기본 좌표는 선택 PI와 다음 PI의 중간입니다.
3. 또는 `평면에서 지정` 후 원하는 위치를 클릭합니다. 하늘색 연결선이 삽입 대상 구간입니다. Esc·우클릭은 삽입 모드를 취소합니다.
4. 내부 PI를 선택하고 `PI 삭제`로 제거합니다. 시·종점은 이 버튼으로 삭제하지 않습니다. 기존 `마지막 점 취소`와 `노선 초기화`는 그대로 제공합니다.

삽입은 선택 PI와 다음 PI 사이의 **제어점 순서**를 지정합니다. 새 좌표를 기존 선분 위로 제한하거나 곡선 위에 자동 투영하지 않습니다. 0.13부터 평면 클릭 추가는 `PI 추가` 도구가 켜져 있을 때만 가능합니다. Shift+클릭도 모드를 우회하지 않습니다.

새 PI는 R/Ls=0으로 시작하고, 기존 점의 R/Ls는 그 점과 함께 이동합니다. 삭제하면 해당 점의 R/Ls만 제거합니다. 내부 PVI의 절대 측점·제어고·Lv는 유지하고 종점 측점만 새 노선 길이에 맞춥니다. 따라서 노선 길이가 바뀌면 종단 구배와 표고 형상도 달라질 수 있습니다.

인접 PI와 1m 미만, 범위 밖·NoData, 기존 곡선의 접선 길이 부족·중첩, 내부 PVI 또는 종단곡선이 노선 범위를 벗어나는 변경은 거절하고 전체 설계를 복원합니다. 반경·완화곡선을 자동으로 줄이지 않습니다. 거절된 편집은 이력이나 유효 토공량을 바꾸지 않습니다. 성공한 삽입·삭제는 각각 undo/redo 한 단계이며 토공량은 다시 계산해야 합니다.

## 0.10 사용자 기준 설계 검토 (main 반영 완료)

기존 창을 저장하고 닫은 뒤 같은 `run-godot.cmd`를 실행하세요. `설계 검토`에서 기준을 입력하고 `검토`를 누릅니다. 초기값은 동작 확인용 예시이며 국내 설계기준을 내장한 값이 아닙니다. C++ DLL은 `kroad_core_v08`, 프로젝트 형식은 v4를 유지합니다.

- 최소 원곡선 반경 R, 각 진입·진출 완화길이 Ls, 최대 절대 종단구배(%), 볼록·오목 최소 K(m/%)를 비교합니다. 기준 0은 해당 비교만 생략합니다.
- R=0이면서 방향이 바뀌는 평면 교점, Lv=0이면서 구배가 바뀌는 종단 교점은 별도 경고로 표시합니다. 직선상 PI와 구배차 0인 PVI는 무곡선 경고 대상이 아닙니다.
- 포물선 구간의 구배 한계 교차 측점을 해석적으로 구합니다. 고정 간격 DEM 표본을 검사하는 방식이 아닙니다. 최대 절대 구배는 접선구배와 포물선의 선형 구배에서 구합니다.
- 행을 선택하면 해당 범위의 중간 측점으로 이동하고 관련 PI/PVI를 선택합니다. 위치와 횡단, 3D를 함께 확인할 수 있습니다. 항목별 사유는 행의 툴팁으로 표시합니다.
- 설정값·집계·지적 항목을 22열 UTF-8 CSV로 내보냅니다. 지적이 없어도 summary 행은 저장합니다. 설계·DEM·기준 변경 시 결과와 CSV 출력을 무효화합니다. 거절된 편집은 기존 결과를 유지합니다.
- 검토 설정과 결과는 프로젝트에 저장하지 않습니다. 설계 형상·DEM·실행 취소 이력을 변경하지 않습니다. 시거·편경사·배수·지형 적합성 등은 검사하지 않으며 지적 없음은 설계기준 적합성 판정이 아닙니다.
- 측점 슬라이더의 기존 0.1% 반올림을 제거했습니다. 토공량 표와 설계 검토표 모두 장거리 노선에서 지정 측점으로 이동합니다.

## 0.11 도로 횡단구배 (main 반영 완료)

기존 창을 저장하고 닫은 뒤 같은 `run-godot.cmd`를 실행하세요. 실행 중인 DLL을 보존하고 `kroad_core_v011...dll`을 별도로 빌드했습니다.

- `좌측 하향(%)`·`우측 하향(%)`를 입력하고 `적용`합니다. 좌·우는 **노선 진행 방향** 기준이며, 양수는 중심에서 바깥으로 낮아지고 음수는 높아집니다. 기본값은 모두 0%입니다. 기능 확인 예: 2/2는 중앙이 높은 단면, -2/2는 한 방향으로 기울어진 단면입니다. 설계기준 권장값이 아닙니다.

## 0.11.1 횡단 뷰 확대·이동

횡단구배는 0.11부터 단면 계산에 반영되어 있었으나 고정 120m 표고 범위에서 작은 차이를 보기 어려웠습니다. 횡단 아래 `도로 확대`는 도로 폭과 구배에 맞춰 축척을 조절하고 중심·좌·우 가장자리 표고를 표시합니다. `전체 맞춤`은 현재 횡단의 지반과 계획면 표고 범위를 자동으로 맞춥니다.

- 프로젝트와 DLL은 0.11과 동일합니다(v5 / kroad_core_v011). 뷰 상태는 저장하지 않습니다.

`--section-smoke`로 작은 구배의 화면 분리, 커서 기준·축별 확대, 드래그, 전체 맞춤과 설계/revision 불변을 검사했습니다. 횡단구배 저장·복원 검사도 통과했습니다.


## 0.12 평면·종단 확대와 이동 (main 반영 완료)

평면·종단 뷰에서도 휠로 커서 위치를 기준으로 확대·축소합니다. 가운데 버튼 드래그는 화면 이동입니다. 각 뷰 아래 `확대`·`축소`·`전체 맞춤` 버튼을 추가했습니다. 종단은 Shift+휠로 측점축만, Ctrl+휠로 표고축만 조절할 수 있습니다. 평면은 가로·세로 비율을 유지합니다.

PI/PVI의 왼쪽 드래그 편집과 우클릭 선택은 유지합니다. 확대 후에도 클릭·이동·PI 중간 삽입·PVI Shift+클릭 추가는 표시 좌표를 실제 설계 좌표로 변환합니다. 편집 드래그 중에는 확대와 화면 이동을 막아 좌표계가 바뀌지 않게 합니다. 종단은 보이는 측점 범위에서 원지반과 계획을 다시 표본화하고 차트 경계에서 잘라 그립니다. 원지반은 화면 표시용 표본이며 상세 지형의 모든 변화를 나타내지는 않습니다.

화면 이동·확대만으로 설계 revision·실행 취소·수량·지형 메시를 갱신하지 않습니다. DEM/프로젝트를 열거나 데모로 바꾸면 화면을 전체 맞춤으로 초기화합니다. 뷰 상태는 프로젝트에 저장하지 않습니다. DLL과 프로젝트 형식은 0.11과 같습니다(kroad_core_v011 / v5).

## 0.13 명시적 PI 추가 모드 (main 반영 완료)

평면 뷰의 상시 점 추가를 제거했습니다. 기본 상태는 기존 PI 선택·왼쪽 드래그 이동입니다. 빈 곳 클릭과 Shift+클릭으로 새 점을 만들지 않습니다.

1. 평면 아래 `PI 추가` 버튼을 눌러 추가 도구를 선택합니다. 버튼이 눌린 상태와 주황색 안내, 십자 커서로 추가 모드를 표시합니다.
2. 지형을 클릭하면 노선 끝에 PI를 연속 추가합니다. 추가 모드에서 기존 PI를 클릭해도 이동을 시작하지 않습니다.
3. Esc, 우클릭 또는 버튼을 다시 눌러 모드를 종료합니다. 이미 확정한 점은 유지하고, 삭제하려면 실행 취소/마지막 점 취소를 사용합니다.

추가·중간 삽입 모드는 서로 배타적입니다. 중간 삽입을 시작하면 추가 모드를 종료하고, 추가 도구를 선택하면 삽입을 취소합니다. 목록에서 PI를 선택하거나 프로젝트·DEM·데모를 새로 열면 선택 모드로 돌아갑니다. 확대·가운데 버튼 이동은 추가 모드에서도 사용할 수 있으며 점을 추가하지 않습니다. 모드 전환 자체는 설계 변경이나 실행 취소 단계가 아닙니다. 프로젝트 v5와 DLL은 그대로 유지합니다.

`--pi-add-smoke`로 기본/Shift 클릭 불변, 버튼 연속 추가, Esc 종료 시 점 보존, 선택·이동·undo, 확대, 삽입 배타성, 우클릭 종료 및 프로젝트 로드 후 모드 초기화를 검사했습니다. 기존 평면·종단 확대, PI 삽입·삭제, 독립 PVI, 횡단 검사를 통과했습니다.


## 0.14 측점 정밀 탐색과 4뷰 연동 (main 반영 완료)

횡단 상단 `STA(m)`에 측점을 입력합니다. 입력 간격은 0.001m이고 노선 범위 안으로 제한합니다. `이동(m)`과 ◀/▶ 버튼으로 일정 간격씩 이동하며 기본 이동 간격은 20m입니다. 기존 슬라이더·종단 클릭·수량/검토표의 행 선택과 같은 측점을 공유합니다.

- 평면에 하늘색 위치·횡단 방향 표시를 추가하고, 종단 선택선·횡단·3D 표식을 함께 갱신합니다.
- 선택 측점의 중심 계획고, 원본 계산용 DEM 지반고, 계획−지반, 종단구배, 현재 곡률의 반경을 표시합니다. 직선은 직선, 결측 지반은 NoData로 표시합니다. 좌표는 정보줄 툴팁에서 확인합니다.
- 평면·종단 아래 `측점 맞춤`으로 선택 위치를 뷰 중앙에 놓습니다. 수동 축척은 유지하며 종단 최초 맞춤은 해당 위치를 확대합니다. 3D는 기존 `측점 보기` 버튼으로 이동합니다. 측점 값만 바꿔서는 카메라를 자동 이동하지 않습니다.
- 측점 탐색은 설계·실행 취소·수량/검토 결과·지형 메시를 바꾸지 않습니다. 선택 측점과 이동 간격은 프로젝트에 저장하지 않습니다. 프로젝트 v5 / DLL v011을 유지합니다.

[측점 탐색 상세](docs/station-navigation.md)를 참조하세요. `--station-smoke`로 입력·이동·슬라이더 동기화, 시종점 제한, 계획고/구배 정보, 평면·종단 맞춤, 3D 표식, NoData 및 설계/revision/지형 업로드 불변을 검사했습니다. 기존 추가 모드·확대·선형 편집·저장·수량·검토 검사도 통과했습니다.

합성 3601×3601 DEM / 약 98.235km 노선 / GTX 1060 6GB에서 연속 측점 이동+Orbit의 중앙값 15.29ms, p95 17.59ms, 지형 업로드 및 revision 변경 0회를 관측했습니다. 사용자 노선의 일정한 성능을 보장하는 값은 아닙니다.


## 0.15 횡단 H:V 1:1 고정 (main 반영 완료)

기존 횡단은 가로·세로 범위를 독립 조절해 기울기가 과장될 수 있었습니다. 이제 화면상의 수평 1m와 수직 1m가 같은 길이가 되도록 하나의 m/화면 픽셀 배율을 공유합니다. `도로 확대`·`전체 맞춤`, 휠 확대, 이동, 뷰 크기 변경에도 동일 비율을 적용하고 `H:V 1:1`을 표시합니다. 이 표시는 가로/세로 비율이며 종이 출력의 절대 축척 1:1이라는 의미는 아닙니다.

횡단의 Shift/Ctrl 축별 확대는 제거했습니다. 어떤 보조키를 눌러도 휠은 양축을 같은 비율로 확대합니다. 이동과 창 크기 변경은 중심 위치와 공통 배율을 유지합니다. 화면 크기에 맞춰 필요한 주변 여백이 생기며, 2% 등 작은 구배는 실제 비율대로 완만하게 보입니다.

`--section-smoke`는 실제 화면 변환 후 1m 가로/세로 길이 일치, 2% 선분 기울기, 커서 기준 확대, 보조키, 이동, 크기 변경·비균일 상위 배율 보정과 전체 맞춤을 검사합니다. headless와 실제 OpenGL 실행에서 통과했고 측점·확대·PI 추가 모드·횡단구배 저장 검사도 통과했습니다. 설계 데이터·수량·프로젝트 v5·DLL은 바꾸지 않습니다.


## 0.16 절토·성토 사면비 분리 (main 반영 완료)

상단 `성토 H:V`와 `절토 H:V`를 각각 입력하고 `적용`합니다. 원지반이 계획 도로면보다 낮은 쪽은 성토비, 높은 쪽은 절토비를 적용합니다. 도로 폭·중심 계획고·좌우 횡단구배는 유지하고 가장자리 바깥 사면과 그에 따른 수량을 갱신합니다. 횡단은 H:V=1:1 화면 표시를 유지합니다.

- 횡단·3D 지형·영향 타일·토공량에 두 사면비를 공유합니다. 절토/성토가 섞인 횡단도 자동 구분합니다.
- 한 번의 적용은 undo/redo 한 단계입니다. 지형을 비동기로 갱신하고 이전 수량·검토 결과는 무효화합니다.

- 토공량 CSV 마지막에 fill_slope_hv/cut_slope_hv를 추가해 21열입니다. 기존 19열 순서는 유지합니다.

기존 실행 창을 저장하고 닫은 뒤 같은 `run-godot.cmd`로 실행합니다. 이전 DLL은 보존하고 `kroad_core_v016...dll`을 별도로 빌드했습니다. [분리 사면비 산식·검사](docs/cut-fill-slopes.md)를 참조하세요.

## 0.18 CAD DXF 내보내기 (main 반영 완료)

## 0.19 설계 대안 보관·전환 (main 반영 완료)

상단 `대안` → 이름 입력 → `현재 설계 보관`으로 현재 노선을 보관합니다. 표에서 길이·PI/PVI 수와 현재 설계와의 일치 여부를 확인하고 `선택 대안 적용`으로 전환합니다.

- 같은 DEM에서 최대20개, 이름은 1~60자입니다. 같은 이름으로 덮어쓰지 않습니다. 보관 후 현재 설계를 바꿔도 보관본은 유지됩니다.

- 대안 적용은 설계 undo/redo 한 단계입니다. 새 지형을 비동기로 갱신하고 이전 수량·표·DXF·검토 결과를 무효화합니다. 보관 자체나 이름 변경은 설계 revision/이력을 바꾸지 않습니다.
- 보관본 이름 변경과 확인 후 삭제를 지원합니다. 삭제는 현재 설계를 지우지 않습니다. 목록 편집은 설계 undo 대상이 아닙니다.
- `프로젝트 저장`으로 현재 설계와 목록을 v7에 저장합니다. v1~v6는 빈 대안 목록으로 읽습니다. 0.18 이하 앱은 v7을 열 수 없습니다. DLL은 v018을 유지합니다.
- 새 DEM/데모 또는 다른 프로젝트를 열면 그 데이터에 맞는 목록으로 바뀝니다. 다른 DEM의 대안을 자동으로 옮기지 않습니다. 길이·점 수 비교를 제공하며 수량/공사비 비교는 이번 범위에 포함하지 않습니다.

## 0.20 보관 대안 토공량 비교 (main 반영 완료)

`대안` 창 아래 `보관 대안 토공량 비교`를 열고 측점 간격·조사 반폭·횡단 간격을 지정해 `계산`합니다. 보관한 전체 대안을 같은 조사 조건으로 순차 계산하며 현재 설계를 전환하지 않습니다.

- 길이·절토/성토·차이·유효/전체 길이와 제외 사유를 비교합니다. 첫 보관 대안이 기준이며 양쪽 모두 전 구간 계산 완료일 때만 Δ절토/Δ성토를 표시합니다.
- 전 구간·유효 구간 부분합·미산출·오류를 구분합니다. 유효 구간이 전혀 없으면 수량을 NA/CSV 빈 셀로 기록하고, 실제 유효한 0m³와 구분합니다. 부분합끼리 수량 차이를 만들지 않습니다.
- 계산 중 진행 대안을 표시하고 `중단`을 지원합니다. 중단은 현재 대안 계산 완료 후 처리하며 미완성 비교 결과는 내보내지 않습니다.
- 설계/DEM/대안 추가·이름 변경·삭제/조사 조건 변경은 결과를 무효화하고 작업 중 결과도 버립니다. CSV는 기준명·산식·각 대안 설정과 상태를 포함한25열입니다.

## 0.22 측점 범위별 토공량 (main 반영 완료)

- 기존 수량 결과를 재사용하고 DEM을 다시 조사하지 않습니다. 경계가 조사 측점 사이에 있으면 절토·성토 단면적을 각각 선형 보간한 뒤 부분 구간 평균단면법으로 적분합니다. 체적을 단순 길이 비율로 나누지 않습니다.

- CSV 21열에는 조사 조건·요청 범위·유효 비율·원본/잘린 구간 경계·보간 단면적·체적·제외 사유를 기록합니다. 프로젝트 v7과 DLL v018을 유지하며 범위 결과는 프로젝트에 저장하지 않습니다.

## 0.23 일정 길이 구간별 토공량 (main 반영 완료)

- 시작/끝/분할 길이 변경은 결과를 무효화합니다. 설계·DEM·원본 수량 조건 변경/재계산 시 파생 창도 비웁니다. 프로젝트 v7·DLL v018을 유지하며 결과는 프로젝트에 저장하지 않습니다.

## 0.24 보관 대안 평면 중첩 (main 반영 완료)

`대안` 창에서 보관본을 선택하고 `선택 대안을 평면에 중첩 표시`를 켭니다. 창을 닫아도 평면에는 보라색 보관 중심선과 주황색 현재 노선이 함께 표시됩니다. 평면 오른쪽 위 `중첩 해제` 또는 체크 해제로 지웁니다.

- 한 번에 보관 대안 하나를 비교하며 실제 네이티브 원곡선·완화곡선의 표시 폴리라인을 사용합니다. PI 직선 연결이나 도로 폭/절성토 외곽선이 아닙니다.
- 동일한 평면 좌표 변환을 사용하므로 확대·이동·측점 맞춤에서도 같은 위치/축척을 유지합니다. 보관 선은 선택/편집 대상이 아니며 현재 설계를 적용하거나 전환하지 않습니다.
- 현재 노선을 편집해도 보관 선은 유지합니다. 이름 변경은 범례만 갱신하고, 표시 중 다른 보관본을 선택하면 참조가 바뀝니다. 선택 삭제·새 DEM/프로젝트/데모는 중첩을 해제합니다.
- 선택 시 표시 형상을 캐시하고 카메라/확대/이동이나 같은 보관본 갱신 시 네이티브 선형을 재생성하지 않습니다. 중첩 켜기/끄기는 설계·undo·revision·DEM·지형 메시를 변경하지 않습니다.
- 중심선 위치 비교이며 같은 측점 번호의 위치 대응·이격 거리·교차 판정이나 종단/3D 중첩은 이번 범위에 포함하지 않습니다. 종단만 다른 대안은 평면에서 겹칠 수 있습니다. 프로젝트 v7·DLL v018은 유지하고 표시 상태는 저장하지 않습니다.

[대안 평면 중첩](docs/alternative-plan-overlay.md)을 참조하세요.

```powershell

```

## 0.25 보관 대안 종단 중첩 (main 반영 완료)

`대안` → 보관본 선택 → `선택 대안 평면·종단 중첩`을 켜면 같은 보관본을 두 뷰에 표시합니다. 보관 계획고는 보라색, 현재 계획고는 주황색이며 녹색 원지반은 현재 노선 기준입니다. 어느 뷰의 `중첩 해제`를 눌러도 함께 해제합니다.

- 같은 절대 STA(m)와 표고 축으로 표시합니다. 보관 종단의 실제 접선/포물선과 계획고 보정을 반영하고 PVI 제어점을 직선으로 연결하지 않습니다.

- 현재 노선을 편집/초기화해도 보관 종단은 유지합니다. 보관 선은 PVI 편집 대상이 아니며 이름 변경/선택/삭제/새 DEM·프로젝트 동작은 평면 중첩과 함께 처리합니다.
- 네이티브 선형을 한 번 구성하고 종단 구간 계수를 캐시합니다. 표시 시 보관 노선의 평면 좌표 계산이나 DEM 조회를 반복하지 않습니다. 설계·undo·revision·지형 메시와 기존 수량 결과를 바꾸지 않습니다.
- 서로 다른 평면 경로의 같은 STA가 같은 지리적 지점이라는 뜻은 아닙니다. 높이 차이의 토공량 환산·보관본 원지반·3D 중첩은 이번 범위에 포함하지 않습니다. 프로젝트 v7·DLL v018을 유지하고 표시 상태는 저장하지 않습니다.

[보관 종단 표시와 좌표 기준](docs/alternative-profile-overlay.md)을 참조하세요.

```powershell

```

포물선 정점/BVC/EVC/끝점·보정고·여러 볼록/오목곡선과 무곡선 종단의 네이티브 값 일치·범위 밖 외삽 거절을 검사했습니다. UI의 범위/축척·확대/이동·캐시·길이가 다른 노선·현재 노선 초기화/undo·표시 해제·삭제/DEM 초기화도 확인했고 기존 평면 중첩·확대/이동·PVI 편집·대안 관리/수량 비교 검사도 통과했습니다.

- 선택 시 보관 노선의 네이티브 공간 검색을 준비하고 측점 이동 시 재사용합니다. 원본 DEM과 지형 메시를 복제/변형하지 않으며 설계·undo·revision·기존 수량 결과를 변경하지 않습니다.
- 현재 노선이 없으면 횡단 위치를 정할 수 없어 횡단은 표시하지 않습니다. 평면/종단 중첩은 기존 동작을 유지합니다. 프로젝트 v7·DLL v018을 유지하고 표시 결과는 저장하지 않습니다.

상단 `DXF`에서 `STA 주석 추가`를 체크하고 주석 간격과 문자 높이를 지정한 뒤 `산출` → `DXF 저장`을 누릅니다. 기본은 주석 끄기이며 기존 중심선·좌우 가장자리 출력은 유지합니다.

- `KROAD_STA_TICK` 표식과 `KROAD_STA_TEXT` 문자를 별도 레이어로 출력합니다. 시점·정규 간격·정확한 종점을 포함하며 종점 1mm 이내의 중복 표식을 합칩니다.
- 주석 간격은 10~10,000m, 최대 2,000개입니다. 문자 높이 0은 도로 폭 기준 자동, 수동 높이는 0.1~100m입니다. CAD 문자 회전은 북쪽 위 평면에서 읽기 쉽도록 −90~90도로 조정합니다.
- 로컬/투영 좌표 선택을 따르며 표식과 문자의 Z는 해당 측점 중심 계획고+보정고입니다. 문자 충돌 자동 회피는 없으므로 간격·크기 또는 CAD 문자 위치를 조절하세요.
- 입력·설계 변경 시 결과를 무효화하고 계산 중 이전 결과를 폐기합니다. 설계·이력·프로젝트 v7·DLL v018은 유지합니다.
